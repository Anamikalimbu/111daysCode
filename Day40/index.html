1. Node Runtime & Event Loop

Node.js is an open-source, cross-platform JavaScript runtime environment built on Chrome's V8 JavaScript engine. Under the hood, Node utilizes Libuv to enable asynchronous, non-blocking I/O.

The Architecture Breakdown

  • V8 Engine: Executes JS code, compiles it to machine code, handles call stack and memory allocation.
  • Libuv: Manages thread-pool execution for heavier work (file operations, cryptography), networking events, and the central loop.
  • Core APIs: Javascript wrappers exposing operating system bindings to the developer.
Is Node Single-Threaded?

Yes, the JavaScript execution thread (call stack) is single-threaded. However, Libuv delegates system tasks to the operating system kernel when possible or utilizes a thread pool (4 threads by default) for operations like file systems, making Node concurrency highly scalable.

Event Loop Phases

The loop runs indefinitely as long as callbacks are pending, transitioning through 6 distinct stages:

Phase Action performed
1. Timers Runs callbacks scheduled by setTimeout and setInterval.
2. Pending Callbacks Executes deferred system I/O errors (e.g. TCP connection refused).
3. Idle, Prepare Used internally by Node for performance configurations.
4. Poll Retrieves new I/O events, runs corresponding callbacks. Can block if empty.
5. Check Executes callbacks scheduled with setImmediate().
6. Close Callbacks Executes teardowns, such as socket.on('close') callbacks.

Microtask Priority Order

Before moving from one phase of the event loop to the next, Node checks and empties the Microtask queues. They execute in this order:

  1. process.nextTick() callbacks (run immediately after the current operation, before any other async tasks).
  2. Promise resolution callbacks (.then, .catch, await resolution). 
Copy Code// Execution Demonstration
console.log('Start');
setTimeout(() => console.log('Timeout (Timer Phase)'), 0);
setImmediate(() => console.log('Immediate (Check Phase)'));
Promise.resolve().then(() => console.log('Promise (Microtask)'));
process.nextTick(() => console.log('nextTick (Tick Queue)'));
console.log('End');

// Expected Output:
// Start -> End -> nextTick -> Promise -> Timeout -> Immediate
Recursive process.nextTick Warning

Because the event loop must empty the process.nextTick queue before moving to the next phase, recursive nextTick loops will starve I/O, freezing the event loop completely. Avoid infinite nextTick recursion!

2. Core Modules (fs, path, os)

Node includes out-of-the-box standard library modules that don't need external installations.

The File System (fs) Module

The fs module has three forms. We strongly recommend the modern Promises-based API for clean codebase design.

Copy Code// 1. Promises-based API (Recommended)
import fs from 'fs/promises';

async function writeAndRead() {
  try {
    await fs.writeFile('example.txt', 'Learning Node Core Modules!');
    const content = await fs.readFile('example.txt', 'utf8');
    console.log(content); // Learning Node Core Modules!
  } catch (err) {
    console.error(err);
  }
}
writeAndRead();

The path Module

Windows and POSIX systems format file paths differently (backslash vs forward slash). To make your code platform-independent, always use the path module.

Copy Codeimport path from 'path';

// Joins pieces using the correct platform separator
const relativePath = path.join('src', 'components', 'button.js');
console.log(relativePath); // Output (Windows): src\components\button.js

// Resolves into an absolute path
const absolutePath = path.resolve('src', 'components', 'button.js');
console.log(absolutePath); // Output: E:\Drive D\NodeJs\Day40\src\components\button.js

// Get details
console.log(path.extname(absolutePath)); // .js
console.log(path.basename(absolutePath)); // button.js
console.log(path.parse(absolutePath)); // returns path components object

The os Module

Collects metadata regarding CPU usage, platform, architectures, and system memory state.

Copy Codeimport os from 'os';

console.log('Platform:', os.platform()); // 'win32', 'darwin', etc.
console.log('CPU Architecture:', os.arch()); // 'x64', 'arm64'
console.log('Free memory (GB):', (os.freemem() / 1024**3).toFixed(2));
console.log('Total cores:', os.cpus().length);

3. CommonJS vs. ESModules

JavaScript originally didn't have modules. Node developed CommonJS (CJS). Later, TC39 standardized ESModules (ESM) for all JS engines. Both formats exist today, and navigating them is a key skill.

Core Differences

Aspect CommonJS (CJS) ESModules (ESM)
Syntax require() and module.exports import and export
Loading Synchronous (loaded dynamically on-the-fly) Asynchronous (resolved at parse-time statically)
File Globals Provides __dirname and __filename Globals don't exist. Recreated using import.meta.url
Top-Level Await Not supported directly. Must wrap in async functions. Fully supported natively at file root.

Resolving __dirname in ESModules

In ESModules, the global variables __dirname and __filename are unavailable. You must use the url and path modules to resolve directory paths relative to the current file:

Copy Codeimport { fileURLToPath } from 'url';
import path from 'path';

// Get current filename (as absolute local path)
const __filename = fileURLToPath(import.meta.url);

// Get current directory path
const __dirname = path.dirname(__filename);

console.log('Current directory:', __dirname);

How to toggle ESModules in your project

  • Option A: In package.json, add the property "type": "module". This turns all .js files into ESModules.
  • Option B: Use the .mjs extension to target ESModules individually, or .cjs to target CommonJS individually.

Copy Codeimport fs from 'fs/promises';
import path from 'path';
import os from 'os';

const args = process.argv.slice(2);
const isRecursive = args.includes('--recursive') || args.includes('-r');
const isJson = args.includes('--json') || args.includes('-j');
const pathArgs = args.filter(a => !a.startsWith('-'));
const targetDir = pathArgs[0] ? path.resolve(pathArgs[0]) : process.cwd();

async function scanDirectory(dirPath, recursive = false) {
  let fileList = [];
  const entries = await fs.readdir(dirPath, { withFileTypes: true });

  for (const entry of entries) {
    const fullPath = path.join(dirPath, entry.name);
    try {
      const stats = await fs.stat(fullPath);
      const detail = {
        name: entry.name,
        absolutePath: fullPath,
        isDirectory: entry.isDirectory(),
        size: stats.size
      };
      fileList.push(detail);

      if (recursive && entry.isDirectory()) {
        const subFiles = await scanDirectory(fullPath, true);
        fileList = fileList.concat(subFiles);
      }
    } catch (e) {
      continue; // skip permissions locks
    }
  }
  return fileList;
}
